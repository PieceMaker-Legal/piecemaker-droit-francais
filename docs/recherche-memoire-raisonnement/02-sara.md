# SARA : écarts avec le raisonnement PieceMaker

## Périmètre de comparaison

Périmètre PieceMaker : le commit `90ec4073c` demandé pour cette comparaison. Les sources SARA sont l’article AAAI-26 et la synthèse AI Magazine : elles décrivent ce que les auteurs déclarent avoir construit, sans donner accès au code de production. Les recherches GitHub ciblées n’ont pas identifié de dépôt public SARA/LCO-BR, sans exclure du code privé ou non indexé.

## Ce qui est déjà couvert et ce qui ne l’est pas

PieceMaker est déjà structuré et traçable : l’agent enrichit un fichier durable de termes, preuves, sources, valeurs et acte ; le vérificateur signale les manques. Le programme conserve, par dossier, le dernier code et snapshot vérifié dans `pm_reasoning_programs` (clé `project_id`, mise à jour par UPSERT avec incrément de révision). Ce stockage garde l’état courant, pas une archive de tous les snapshots. L’historique Git local du dossier ([`docs/historique-dossier.md`](../historique-dossier.md)) exclut explicitement `.piecemaker/`, qui contient le raisonnement : il conserve d’autres changements de fichiers, mais ne versionne donc pas ce raisonnement. L’accès SQL aux pièces, personnes, mentions et citations est décrit dans [`docs/outil-sql.md`](../outil-sql.md).

Réciproquement, l’agent PieceMaker reste responsable de la construction et de l’interprétation du raisonnement. Le vérificateur contrôle la forme, les liens et les conditions annoncées, et conduit une boucle d’amélioration par erreurs et manques ; il ne remplace pas le raisonnement juridique par un moteur d’inférence général. Les sources examinées ne permettent pas d’affirmer que SARA fait cette substitution non plus : l’article décrit une chaîne de modules LLM, un graphe de connaissances, de la recherche et des contrôles de couverture.

Pour une mémoire qui grandit au fil du traitement d’un dossier, l’idée transposable est une couche relationnelle avec provenance pour acteurs, prétentions/demandes, preuves, arguments, précédents et leur présence dans l’acte, actualisée à l’arrivée de pièces. PieceMaker conserve déjà un dernier état de raisonnement par dossier, mais les fichiers examinés ne montrent pas d’archive sémantique de ses révisions ni de synthèse automatique des nouveaux apports. SARA étaye le graphe de cas et le contrôle de couverture, mais ne démontre pas une mémoire longitudinale apprenant d’une affaire à l’autre : le JUR-KG est un fonds jurisprudentiel en expansion ; le graphe d’affaire représente chaque dossier.

## Limites des éléments publics

L’article AAAI évalue cinq affaires et décrit les retours de magistrats : cela documente un usage, pas une comparaison avec PieceMaker ni une supériorité générale. Wiley détaille les modules et ontologies, mais reste une description publiée. Sans code SARA ou spécification LCO-BR publique identifiée, leurs contrôles exacts et la persistance des graphes restent incertains.

Sources principales : [article AAAI-26 de SARA](https://ojs.aaai.org/index.php/AAAI/article/download/41425/45386) ; [article AI Magazine / Wiley](https://onlinelibrary.wiley.com/doi/10.1002/aaai.70076). La page Wiley a renvoyé HTTP 403 à la vérification finale des liens ; ses extraits publics indexés ont été consultés. L’article AAAI est accessible et reste la source principale pour les capacités rapportées.
